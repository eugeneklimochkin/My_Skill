# Формат оценки

## 1. Чистовой документ

Если пользователь просил документ «на подпись», «на подачу» или чистовой текст:

- провести приемку внутренне;
- выдать только готовый документ;
- не добавлять статус, таблицу критериев и отчет о процессе;
- при невозможности полной приемки кратко назвать блокирующий недостаток вместо имитации готовности.

## 2. Проверка документа

Начинать с одного статуса:

- ГОТОВО;
- ТРЕБУЕТ ДОРАБОТКИ;
- НЕПРИГОДНО.

Затем приводить только значимые непрохождения:

| Критерий | Уровень | Точное место | Основание и источник | Исправление |
|---|---|---|---|---|

После таблицы указывать:

- сведения, требующие подтверждения;
- диагностический результат: пройдено X из Y применимых критериев;
- пределы проверки и недоступные источники.

Не перегружать отчет перечнем несущественной редакторской правки.

## 3. Benchmark-отчет

Для каждой конфигурации показывать:

| Показатель | Значение |
|---|---|
| Модель и версия | |
| Промпт и навыки | |
| Число заданий и запусков | |
| Полная приемка | X из Y, процент |
| Критерии | X из Y, диагностический процент |
| Блокирующие непрохождения | |
| Охват материалов | |
| Время | |
| Стоимость | |
| Согласие оценщиков | |

Вывод должен отвечать не «кто набрал больше процентов», а:

1. какая конфигурация чаще выдает полностью готовый результат;
2. какие категории критических ошибок сохраняются;
3. на каких практиках вывод устойчив;
4. какие ограничения не позволяют распространить результат.

## 4. Запись отдельного критерия

Использовать краткую форму:

- ID и название;
- pass, fail, na или unverified;
- фрагмент результата;
- источник;
- причина не более нескольких предложений;
- требуемое исправление для fail или unverified.

Не использовать скрытую цепочку рассуждений как обоснование. Основание должно быть проверяемым по результату и источнику.
